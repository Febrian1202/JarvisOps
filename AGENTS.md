# AGENTS.md — JARVIS OPS

IT Service Management monorepo. **Design phase is complete; implementation has barely started.** `docs/` is dense and authoritative; the code is still near-scaffold. Expect to be writing net-new code, not modifying existing features.

## Repo layout

```
apps/api/    Laravel 13.17 + Sanctum 4 (PHP ^8.3, local runtime is 8.5)
apps/web/    Next.js 16.3 + React 19 + Tailwind v4 (App Router, src/app)
docs/        ~6.3k lines of approved design docs (Indonesian)
```

There is **no root manifest, no Makefile, no docker-compose, and no `.git`** — despite what `README.md` and `docs/product/ROADMAP.md` describe. Every `make up` / `make test` command in the README is aspirational (Phase 0 work). Run commands from inside `apps/api` or `apps/web`.

## Hard conventions that differ from framework defaults

- **Every API response uses one envelope**: `{ success, message, data, meta? }` / `{ success, message, errors }`. Never return a bare Eloquent Resource or a raw 422 body. No `links` in `meta`.
- **Frontend never calls Laravel directly.** Next.js Route Handlers act as a BFF; the Sanctum token lives in an httpOnly cookie and is attached server-side. A client component calling `http://localhost:8000` is a bug.
- **Authorization is core Laravel Gate/Policy only.** One role per user via `users.role_id`. Do not add `spatie/laravel-permission`.
- **SLA is snapshotted onto each ticket** (`sla_duration_minutes`, `sla_deadline`) at creation — never joined live from the priority table. Breach state is also recomputed defensively at query time, not trusted from the scheduler alone.
- All durations are integer **minutes**; timestamps ISO 8601 UTC; fields `snake_case`; routes `kebab-case` plural.
- Attachments go to a private disk and are served only through a controller that runs the parent ticket's policy. Limit 5 MB; JPG/JPEG/PNG/PDF only; validate MIME **and** extension server-side.
- Notifications are DB rows + 30s frontend polling. No WebSocket, no broadcasting, no email/SMTP.
- The SLA scheduler runs every 5 minutes as its own process (`php artisan schedule:work`, separate container in prod) — FrankenPHP classic mode only serves HTTP.
- Frontend stack is pre-chosen (ROADMAP §2): shadcn/ui, TanStack Query, Recharts, react-hook-form, zod. Don't introduce alternatives.
- Docs and user-facing prose in this repo are **Indonesian**. Match it when editing `docs/` or `README.md`.

## Backend commands (`apps/api`)

```bash
php artisan test                      # or: vendor/bin/phpunit
php artisan test --filter=SomeTest    # narrowest run; prefer this
vendor/bin/pint --dirty --format agent   # required after editing any PHP
composer dev                          # php artisan dev (concurrent dev processes)
```

Testing reality check: **PHPUnit 12.5 is installed, Pest is not** (`vendor/pestphp` absent). README and ROADMAP call for Pest 5 + `phpunit/phpunit ^13.3` — that is a planned migration, so `php artisan test --parallel` and Pest syntax will fail today. Create tests with `php artisan make:test --phpunit {name}`.

Tests run against **SQLite in-memory** (`phpunit.xml`), but `apps/api/.env` points at **MySQL** (`DB_DATABASE=JarvisOps`, root/root) while `.env.example` still says sqlite. Don't assume the committed example reflects the working setup.

Health endpoint today is `/up` (`bootstrap/app.php`), not the `/api/health` the README promises. API exceptions already render as JSON for `api/*`.

## Instruction files and tooling

- `apps/api/AGENTS.md` is **generated by Laravel Boost** and `apps/web/AGENTS.md` is **regenerated by `next dev`**. Don't hand-edit them expecting the change to survive; commit the regenerated block rather than reverting it.
- Boost's `.ai/rules` mechanism is referenced by `apps/api/AGENTS.md` but the directory does not exist yet — skip that step until it does.
- `apps/api/opencode.json` registers the `laravel-boost` MCP server. It only loads when opencode starts from `apps/api` (config resolution walks up from cwd), so Boost tools like `database-schema` and `search-docs` are unavailable in a root-level session. Start in `apps/api` for backend work if you want them.
- Project skills live in `.opencode/skills/`: `laravel-best-practices`, `testing-best-practices`, `tailwindcss-development`, `infer-conventions`. Load the relevant one before writing code in that domain. Note `.opencode/` is gitignored at the root, so these are local-only.
